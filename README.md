# 汇声磁带 · 多通道试转录校准

按带速比对双轨试录段，交付需要补录的卷号、区间与复录工序。

模拟团队为 汇声口述史录音室，7 人团队，每天用两台开盘机转录馆藏双轨磁带。。机台操作员在测试音与静音片段上量测电平、高频损失、相位、抖晃与底噪，汇总成校准表，交班时与近期合格记录逐栏比对。

- 不同带速的相位与底噪基线不同，合并判读会误报。
- 逐栏阈值看不到高频、电平和相位变化之间的常见关联。
- 复录工单去掉了试录区间和参考段，接班人员需要回找源表。

开盘机试录日志与音频分析仪导出的双轨测量值。归档员先把近期同台架合格数据分成参考与留出样本。 复录工位按卷号和时间区间补录。质检员回填复测读数，再决定是否交付编目。

## 业务模块

| 模块 | 工作内容 | 核心实体 |
|---|---|---|
| 试录测量表 | CSV 校验、预览实测字段、以完整数据内容的 SHA-256 去重、追溯版本和下载原始数据 | 数据版本 |
| 拟合校准基线 | 按版本与领域参数创建计算单，由独立进程计算；从排队、成功或失败状态追溯 | 计算单 |
| 试录处置单 | 按业务字段查看度量、比较与排序，下载计算结果 | 计算单及其结果 |
| 复录交班 | 对结果样本作签发或暂缓，记录理由，导出选中样本并查看审计时间线 | 交接记录 |

## 算法及口径

**同带速标准化 PCA · 重构残差与主成分距离**。先按带速分组，仅用参考段拟合均值、标准差和两维 PCA。对每条试录段计算标准化重构残差平方和 Q，以及按主成分方差归一的距离平方 T²。综合分取 max(Q / 参考段的平均 Q, T² / 2)，再除以同速留出合格段的经验分位边界。相对分超过 1 时建议复录。用前两主成分的方差归一距离找最近参考段，按残差或偏离最大的量测项给出复录工序。同速至少需 12 条参考与 8 条留出，参考测量无变化、残差退化、区间倒置或缺少待检段时会提示修正。录音波形由上游分析仪量测，页面处理表内读数。

录入参数 **留出合格分位**，默认 0.95，允许范围 0.8–0.99。每档带速从留出合格段单独估算。调高分位会提高该档复录门槛。

演示集 `HS-1125-双轨试录与合格参照.csv` 由 `backend/src/business/demo.py` 用固定数据或固定随机种子生成。工作台保留每次运行使用的输入版本、参数、结果和签审人。业务判断由服务端执行，前端图表直接读取返回的数值。

## 一天的工作剧本

1. 08:40 载入 HS-1125-双轨试录与合格参照.csv，确认两种带速各有 28 条参考段与 12 条留出合格段。
2. 08:55 核对 HS-064A 的校准音区间，试录段 TR-A01 对应卷内 40–60 秒。
3. 09:05 以工程师账号创建校准批次，采用 0.95 留出合格分位边界。
4. 09:10 检查两档带速是否各自拟合基线，确认 TR-A01 的相对分不超过 1。
5. 09:20 在处置单定位 HS-077B 的 TR-B04，卷内 210–230 秒，抖晃读数 0.62%。
6. 09:30 导出复录交班表，交付卷号、区间、同速参考段与建议工序。
7. 10:15 复录技师按交班单复测带速稳定性，安排 HS-077B 的同段回录。

## 技术与配置

| 服务 | 技术与职责 |
|---|---|
| frontend | HTML/CSS/JS ES 模块，Nginx 静态页面与同源 API |
| backend | Python 3.11、FastAPI、SQLAlchemy、JWT |
| worker | Python 后台进程，使用 DB 的原子认领、租约与重试，输出 CSV |
| db | PostgreSQL 16，存账号、版本、计算单和审计 |
| redis | Redis 7，通知 worker 尽快拾取，任务状态由数据库持久化 |

`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT` 管理回环端口，`JWT_SECRET` 为签名密钥，`DB_PASSWORD` 为应用数据库口令，`COMPOSE_PROJECT_NAME` 控制该栈的命名空间。

本地 Python 开发可用 `docker compose up -d db` 启动关系库，并另起一个仅绑定回环的 Redis。Compose 内的 Redis 通过容器网络连接。用 Python 3.11 安装 `backend/requirements.txt` 后，进入 backend 目录，设置 `DATABASE_URL`、`REDIS_URL`、`JWT_SECRET`、`ARTIFACTS_DIR`、`SEED_DEMO`，分别运行 `uvicorn src.main:app --reload`、`python -m src.worker`。ARTIFACTS_DIR 需已存在且由两进程共享。前端可使用 Compose Nginx 镜像并重建以加载修改，或用已有 Nginx 反向代理本地 Python 端口。

`backend/src/business/` 保存本题字段、生成器和算法，`backend/src/services/` 处理资源生命周期，`backend/migrations/` 是初始关系模式，`frontend/src/` 按页面、API、会话、组件、路由及样式组织。前后端枚举分别在 `backend/src/constants/workflow.py` 和 `frontend/src/constants/enums.js`。角色用于 JWT 路由与表单权限，计算状态用于队列与结果页，签审决定用于交接页、审计和签发导出。
